# I18N.md

How Fileship is translated, and the rules every translated string follows. The dashboard and the desktop app are translated into Turkish, Simplified Chinese, German, French and Italian. The telemetry panel stays in English. English is the source language and the fallback.

## Where messages live

| Part                     | Catalog                                                    | Loaded by                                                                             |
| ------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| ui layer                 | `packages/ui/i18n/locales/<code>.json` (`common`, `error`) | `packages/ui/i18n/i18n.config.ts`, bundled                                            |
| Dashboard (UI and API)   | `apps/dashboard/i18n/locales/<code>.json`                  | `@nuxtjs/i18n` locale `file` in `nuxt.config.ts`; the server uses the same files      |
| Desktop (renderer, main) | `apps/desktop/i18n/locales/<code>.json`                    | `apps/desktop/i18n/messages.ts`, used by `i18n/i18n.config.ts` and `electron/i18n.ts` |

- Each locale is one file. Its top-level keys group the messages by page or area (`files`, `instance`, `errorsAuth`, `tray`, ...); keys are camelCase.
- `en` and `tr` must have the same keys. `pnpm lint:i18n` (`scripts/check-i18n.mjs`) checks this, rejects empty strings and compiles every message; `pnpm lint` runs it.
- ESLint (`@fileship/eslint-config/i18n`) rejects raw text in templates (`no-raw-text`, including `title`, `label`, `description`, `placeholder`, `aria-label` attributes) and keys that do not exist (`no-missing-keys`).
- Message syntax is vue-i18n: `{name}` for parameters, `a | b` for plurals (`t('files.count', { count: n }, n)` or `t('files.count', n)`), and the characters `@ $ | { }` must be written as `{'@'}` etc. when they are literal text. Emails in placeholders need `{'@'}`.

## Code

- Templates: `$t('ns.key')`. Scripts: `const { t } = useI18n();` in components, `useNuxtApp().$i18n.t` in plain composables and utils.
- Never build a sentence from pieces (`t('delete') + ' ' + name`). Use one message with a parameter.
- Never compare a translated message. The API sends a flag in `data` when the client must react to an error (for example `data.totpRequired`).
- Dates: `const date = useDate();` then `date(value).fromNow()`, `date(value).format('lll')`. Use localized formats (`L`, `LL`, `LLL`, `ll`, `lll`, `LT`), never English patterns such as `MMM D, YYYY`.
- Numbers: `new Intl.NumberFormat(locale.value)`; `filesize(size, { locale: locale.value })`.
- Dashboard server: `throw apiError(status, 'errorsX.key', params?)` (`server/utils/i18n.ts`). Zod messages are keys (`.min(3, 'errorsAuth.usernameMin')`) and invalid bodies are thrown with `throw invalidBodyError(body.error)`, which translates them. `translate(key, params)` works anywhere inside a request. Log messages (`createLog`) stay in English.
- Desktop main process: `t('ns.key', { name })` from `electron/i18n.ts`. It supports `{name}`, `{'x'}` literals and `a | b` plurals with `count`.
- Values that are keys (`FILE_CATEGORIES[x].label`, `PII_REASONS[x]`, desktop `EXPIRATIONS`, `COMPRESSIONS`) are rendered with `$t(value)`.

## Writing Turkish

The goal is an interface that reads as if it had been written in Turkish. Never translate word by word: read what the English string does on the screen and write what a Turkish product would say there.

- **Short and plain.** Turkish UI text is shorter than a literal translation. Drop filler: "Are you sure you want to delete this file?" → "Bu dosya silinsin mi?", "Successfully saved" → "Kaydedildi", "Something went wrong" → "Bir sorun oluştu", "No files yet" → "Henüz dosya yok", "Copied to clipboard" → "Panoya kopyalandı".
- **Address.** Use the singular "sen" form, the way modern Turkish apps do: "Kullanıcı adını gir", "Hesabın yok mu?". Never "siz", "-iniz", "-ınız" or "lütfen". Prefer impersonal or passive descriptions when they read naturally: "Dosyalar 30 gün sonra kalıcı olarak silinir".
- **Buttons and menu items** are short imperatives: "Kaydet", "Yükle", "Sil", "Çöpe taşı", "Klasör oluştur", "Bağlantıyı kopyala". Titles and labels use sentence case: "Yeni klasör", not "Yeni Klasör".
- **Errors** say what failed with "-namadı / -nemedi": "Dosya yüklenemedi", "Bağlantı oluşturulamadı", "Sunucuya ulaşılamadı". Validation: "Kullanıcı adı en az 3 karakter olmalı".
- **Success toasts** use the passive past: "Dosya silindi", "Ayarlar kaydedildi", "Bağlantı kopyalandı".
- **Confirmations** ask a short question and say the consequence: title "Bu dosya kalıcı olarak silinsin mi?", description "Bu işlem geri alınamaz.", button "Kalıcı olarak sil".
- **Empty states**: "Henüz not yok", "Sonuç bulunamadı", "Burada gösterilecek bir şey yok".
- **Parameters and suffixes.** Turkish suffixes depend on the word, so never glue a suffix to a parameter (`{name}'i`, `{count} dosyayı`). Put the parameter where it needs no suffix: "Silinen: {name}", "{name} silindi", "{name} adlı klasör", "{count} dosya taşındı".
- **Counts.** A noun after a number stays singular: "5 dosya", "1 dosya". Turkish plural messages therefore usually have one form; if the English has `x | y`, the Turkish may be a single form or use the same number of choices.
- **Capital İ.** Write "İ" and "ı" correctly. In code use `toLocaleUpperCase(locale)` / `toLocaleLowerCase(locale)`.
- **Punctuation.** Descriptions end with a period like the English; labels, buttons and toasts do not. Use "…" only where the English does.
- Keep brand and technical names as they are: Fileship, Fileship Harbor, ShareX, S3, SFTP, FTP, OCR, GIF, TOTP, WebDAV, API, URL, IP, MIME, EXIF, ffmpeg, CPU, GPU, RAM.

## Chinese, German, French and Italian

The same goal applies: native product text, never word by word. Translate from English and read the Turkish for intent and brevity.

- **de**: informal "du" (lowercase), like modern apps. Buttons: infinitive ("Speichern", "Hochladen", "In den Papierkorb verschieben"). Errors: "Datei konnte nicht hochgeladen werden". Success: "Datei gelöscht". Confirm titles: "Diese Datei endgültig löschen?". Avoid long compound monsters where a shorter phrase exists; avoid anglicisms when a normal German word exists, but "Link", "Upload", "Backup", "Passkey", "Token", "Dashboard", "Screenshot" are fine.
- **fr**: "vous", like Google/Apple French UIs. Buttons: infinitive ("Enregistrer", "Importer", "Placer dans la corbeille"). Errors: "Impossible d'importer le fichier". Success: "Fichier supprimé". French typography: a non-breaking space (U+00A0) before `:` `?` `!` `;` and inside « » if used; prefer ’ or ' consistently (use the straight ' ). Sentence case.
- **it**: "tu", like Apple/Google Italian UIs. Buttons: imperative/infinitive as Italian UIs do ("Salva", "Carica", "Sposta nel cestino", "Elimina definitivamente"). Errors: "Impossibile caricare il file". Success: "File eliminato". Sentence case.
- **zh** (Simplified Chinese, mainland conventions): use 你 (not 您). Full-width punctuation （，。：？！）; put a half-width space between Chinese and Latin words, numbers or `{params}` (e.g. "上传 {count} 个文件", "Fileship Harbor 已启用"). Concise. No plural forms needed (single form). Buttons are short verbs (保存, 上传, 移到回收站, 永久删除).
